# Feature: BME680 environmental sensor v1

Temperature, pressure, humidity, and gas resistance from a Bosch BME680 over I2C ([ADR-009](../adr/009-i2c-sensor-drivers-in-tamer.md)); SPI is out of scope for v1.
Gas resistance is raw ohms; air-quality interpretation (humidity correction, baselines, IAQ) is the consumer's job.
Ported from donated source whose own host tests stay with the request; none of the v1 tests below exist in this repo yet.

## Decisions
| Decision                                                                       | Reason                                                          | Rejected Alternative                             |
|:-------------------------------------------------------------------------------|:----------------------------------------------------------------|:-------------------------------------------------|
| `bme680` = pure core; driver needs `bme680` + `hal`                            | Compensation math stays usable without `embedded-hal`           | `bme680 = ["hal"]` — couples math to the bus     |
| `bme680` feature adds no dependency                                            | Only `core` f32 `+ - * /`; keeps BME680 float code opt-in       | `micromath` — no trig needed (cf. ADR-003)       |
| Move parsing, encodings, ctrl bytes, status bits, durations into the pure core | Leaves the driver as I2C transactions plus a delay loop         | Keep register logic inside the driver            |
| Compute `res_heat` from per-unit trim (`par_g1..g3`, range, val)               | Per-unit correct heater target; pure f32, host-testable         | Fixed `0x73` preset — varies unit to unit        |
| Fixed 320 °C / 150 ms heater target in the driver                              | Simple v1 profile; its suitability is validated on hardware     | Parametric heater profiles (out of scope)        |
| Typed `Oversampling` / `IirFilter` enums as positional args                    | Invalid values unrepresentable; still no config struct          | Raw `u8` counts; an `Oversampling { .. }` struct |
| Value types keep private fields behind accessors                               | Public f32 fields freeze the API; matches `mpu6050::RawReading` | Public struct fields                             |
| Failed `new` returns `(Error, I2C)`; `release()` returns the bus               | The caller always gets the bus back                             | Dropping the bus on init failure                 |
| `Error::Bus(E)` keeps the HAL error                                            | Keeps diagnostics; portable code inspects `kind()`              | Map to `ErrorKind` only — loses detail           |

## API surface
- `CalibrationData::from_raw(&[u8; 25], &[u8; 16], res_heat_range, res_heat_val, range_sw_err) -> Result<Self, CalibrationError>` is opaque, with no getters.
- `parse_raw(&[u8; 15]) -> RawReading` and `compensate(&CalibrationData, &RawReading) -> Reading` expose values only through accessors (°C, hPa, %RH, `Option` Ω).
- `res_heat(&CalibrationData, target_c, ambient_c) -> u8` and `measurement_duration_us(osrs_t, osrs_p, osrs_h) -> u32` are pure free functions.
- `Bme680::new(i2c, address, &mut delay) -> Result<Self, (Error<E>, I2C)>` takes `0x76` or `0x77`; `measure` and `release(self) -> I2C` complete the driver.

## Measurement contract
- `measure` computes `required_ms = (measurement_duration_us + 150_000 if read_gas).div_ceil(1000)` in `u32` and rejects `timeout_ms < required_ms` before any bus write.
- Before triggering, it reads the data block, which drains a stale sample whether `new_data` clears on read or on trigger.
- After the trigger it waits `required_ms`, then polls `meas_status_0` every 1 ms until `new_data` is set and `measuring` / `gas_measuring` are clear.
- `timeout_ms` budgets only the driver's own `DelayNs` waits (saturating), not wall-clock or bus time, which would need a clock or HAL config; exhausting it returns `Error::Timeout`.

## Constraints
- `no_std`, alloc-free, no `unsafe`, MSRV 1.88; no new dependency for the default `tamer` build.
- `measure` keeps an explicit `read_gas` flag; the heater ambient input is the last measured temperature, or 25 °C before the first.
- Gas resistance is `None` when not requested, when `gas_valid_r` is clear, or when `heat_stab_r` is clear.
- Bus faults, a wrong chip ID (`0x61`), timeouts, and degenerate calibration (all `0x00` / `0xFF`) return `Err`, never a panic or NaN.
- Startup: the caller keeps VDD / VDDIO stable for the 2 ms datasheet start-up time; `new` soft-resets, waits 10 ms (Bosch `BME68X_PERIOD_RESET`), then reads chip ID and calibration.
- Port fixes, both misdecoded in the source: `par_h1 = (E3 << 4) | (E2 & 0x0F)`, `par_h2 = (E1 << 4) | (E2 >> 4)`, and signed `range_sw_err = ((reg & 0xF0) as i8) >> 4`.

## Required tests (host)
- Calibration: distinct value per field; humidity nibbles with `E2 = 0xAB`; negative `sw_err` and `heat_val`.
- Reference: a real device dump vs the Bosch BME68x SensorAPI v4.4.8 float path, recording provenance and units (°C, hPa, %RH, Ω).
- Tolerances: 0.01 °C, 0.01 hPa, 0.01 %RH, 0.1 % gas; `res_heat` and `measurement_duration_us` match Bosch exactly.
- Edges and registers: humidity clamp at 0 / 100, all 16 `gas_range` values, every enum encoding, ctrl byte layout, `parse_raw` shifts.
- Driver (`MockI2c`): wrong chip ID returns the bus, NACK keeps `E`, timeout, short budget, gas skipped / invalid, stale-then-fresh sample.
